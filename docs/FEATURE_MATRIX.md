# UNITY end-state feature matrix

Status definitions: **Implemented** = code exists; **Verified offline** = automated tests prove stated offline behavior; **Planned** = no operational implementation. Public discovery is not provider connection.

| Area | Personal alpha now | Complete-product acceptance gate |

| AI discovery | OpenRouter and capped Hugging Face public catalogs | Continuously updated, deduplicated compatible catalogs with separate actual availability |
| Model routing | Verified offline policy and planning functions | At least two real authorized providers with hard budget guard and provider-side billing verification |

## Acceptance gates before any real client data
1. Dedicated non-production infrastructure exists; nothing is written into an unrelated project's database.
2. Identity is verified server-side and authorization is independently enforced at every integration.
3. Two-user isolation and cross-project access tests pass.
4. Secret storage and revocation are functional.
5. The zero-paid-API policy is verified against real billing observations, not catalog metadata.
6. Backup and restore work and are tested.
7. Task execution is traceable, and approval applies only to its exact action and resource.

## 90-day personal validation
Measure completed tasks against prespecified tests, required rework, free/premium usage, operating cost, invalid completion claims, actual cross-project isolation and weekly willingness to use UNITY. Personal success is not proof of general product-market fit.
